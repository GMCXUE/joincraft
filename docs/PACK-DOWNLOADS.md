# 整合包下载与本机复用

截图中的「下载游戏资源与依赖」下载的是 Minecraft 的资源、依赖和运行文件，并非整个整合包 ZIP 的上传进度。导入清单包通常仍需补齐这些文件；上传 ZIP 本身不表示游戏环境已安装。

当前优化：

- 游戏资源、Java 文件和模组批量下载默认 16 并发，内部可配置 1–32；大文件先进入队列，减少末尾等待。
- 优先复用已校验目标、Joincraft 内容缓存、用户已添加的 PCL 游戏目录及其他已安装的 Joincraft 实例。PCL 隔离版本中的模组也可复用，改名的原版客户端 JAR 仍按固定摘要匹配。
- 复用要求摘要和大小一致，复制到独立实例并再次验证，不链接或改写 PCL 文件，不复制存档。没有摘要的外部文件不会复用。
- 缓存以临时文件校验后原子保存；本地文件损坏或缺失则回到网络下载。多地址依赖先尝试其他地址，再重试失败的地址；连续 15 秒没有响应则切换尝试。
- 并发进度按增量累加字节与文件数，不再对数千项文件每次重新求和。进度显示已复用数量，下载速度仅统计网络字节。
- 房主上传前将已选择压缩包保留在安装目录的 `downloads/<SHA-512>.mrpack`，后续安装直接使用这份副本；即便原文件删除或客户端重启也不必再次从 VPS 下载。仍需验证当前房间权限与固定版本。

使用已有 PCL 资源时，先在游戏库「添加已有目录」中选择 PCL 目录或 `.minecraft`；客户端只搜索用户已添加的路径。升级前已上传而没有保留副本的文件无法凭空恢复，可重新选择同一整合包文件发布，已有同摘要文件不会重复上传。

## 验证

`npm run test:packs` 覆盖安装、上传与下载完整性、并发上限、取消、PCL 复用、改名 JAR、损坏回退、缓存和进度计数。

`npm run benchmark:packs` 使用模拟响应延迟、真实 SHA-1 校验和磁盘写入。128 个 64 KiB 文件，每次响应等待 60 ms，每 16 KiB 等待 5 ms；本机一次结果为 4 并发 2.999 秒、16 并发 0.762 秒，约 3.94 倍。该结果只衡量延迟模型下的调度，不能用于承诺用户真实网络的下载速度。已有正确本地文件的回归测试未发出对应网络请求。

首次全新安装仍受资源站、网络、磁盘与加载器处理耗时影响。此版未接入新的第三方镜像；Windows 真实整合包安装和用户网络速度需在更新客户端后验证。本机测试文件均为模拟内容，不执行游戏和 Java。
