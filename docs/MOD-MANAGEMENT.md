# 客户端模组管理

入口：客户端首页 → 版本设置 → 模组。网页不读取本机模组目录。本轮只支持 Joincraft 自有实例；CurseForge 搜索下载暂缓，原有整合包导入不受影响。

## 日常操作

- 「已安装」可按名称、Mod ID、作者搜索，筛选启用、停用和需检查的文件。一个 JAR 中多个 Mod 共用文件选择项，详情显示各自信息。
- 导入、启停、移除、安装和更新之前，原版实例会复制为独立编辑副本。只复制游戏环境，存档仍留在原实例；编辑副本不会自动读取原世界。若需继续原世界，请退出游戏后自行复制该实例的 saves 目录。
- 停用文件保留为 `.jar.disabled`。移除和更新保留备份，可在「恢复备份」中恢复。游戏、整合包任务或其他模组任务运行时禁止写入。
- 「下载模组」使用 Modrinth，默认过滤当前 Minecraft 与加载器。选择版本后先查看前置、冲突和更新说明；必需前置自动加入，可选前置手动勾选。
- 「检查更新」对已选文件检查；未选时检查全部。默认仅推荐较新的兼容正式版。勾选后预览更新，不自动批量升级。版本锁定按文件哈希保存。
- 元数据声明不能证明完整运行兼容性；未知来源不会根据文件名猜测。Forge、NeoForge、Fabric、Quilt 与旧式 mcmod.info 均支持解析，且不会执行 JAR。

## 房间新版本

房主在房间选择整合包时选择「编辑副本」，检查文件差异、版本名称和新增配置/脚本后确认发布。默认包含原包收录范围及当前启用的模组，新生成配置由房主勾选加入。

导出使用标准 `.mrpack`：可验证的下载引用继续保留 URL、大小和哈希；本地文件作为 overrides 收录。上限仍为 600 MB。存档、账号数据、运行缓存和客户端外置的联机辅助模组不会上传。上传复用现有 4 MB 分块、哈希校验与房主权限检查。

服务端保存当前版本的内容哈希。成员通过带鉴权的 `GET /api/rooms/:id/pack/manifest?sha512=...` 获取路径/大小/哈希；新版本的 `baseSha512` 指向导出来源，只与该来源比较，不用同名整合包猜测来源。确认后安装成独立实例，旧实例及存档保留。房间切换版本期间使用旧哈希会收到 409。

房主发布成功后复核本地文件，直接登记为该版本，无需再下载。登记使用不可变归档文件和原子注册文件，原版仍保留。之后再编辑会创建下一份副本。房间实时通知继续走现有 WebSocket。

## 本地数据与恢复

实例目录为 `<安装目录>/instances/<UUID>/.minecraft`，旁边保存 `instance.json`、原始归档和 `mods-state.json`。备份在 `mod-history/<事务 UUID>/`，包含修改前文件与日志；下载暂存于 `mod-downloads/`，导出在 `exports/`。这些均为本地数据，不提交 Git。

写入前备份并记录 pending 日志，完成后登记 committed；失败恢复旧文件。下次访问或从首页、游戏库、房间启动前，未完成事务先恢复。备份保留在本机，删除整个实例也会删除其备份。

Modrinth 元数据直接通过官方 API 查询，包含项目 User-Agent、缓存、超时和限流处理。JAR 下载复用 16 路并发引擎、按哈希复用缓存和现有 VPS 固定来源加速，失败可回源；不传输微软令牌或账号信息。

## 验证

- `npm run test:mods`：解析、复制隔离、事务恢复、来源识别、依赖、下载、更新、房间发布和鉴权测试。
- `npm run test:mods:large -- /绝对路径/整合包.zip`：只在临时目录读取内置 JAR，再构造 425 文件扫描，不执行游戏。
- `npm test`：全量回归。Windows 真实游戏启动、文件占用和多人联机仍需实机验收。

客户端本地模组功能可独立使用。房间新版本发布及差异同步还需要配套的网页资源与后端清单接口上线；本轮只提交源码和生成测试包，不自动部署生产。旧网页会提示刷新/更新，避免将编辑副本误当作原归档发布。
