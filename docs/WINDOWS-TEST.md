# Windows Java 版联机验收

当前版本：0.8，本地连接程序 + 网页房间 + WebSocket 中继。2026-11-12 按用户要求只做协议模拟与自动化测试，尚未使用真实 MC 客户端进入世界，也未做跨网络或 Windows 实机验收。

## 测试前准备

- Windows 安装 Node.js 22.13 或更高版本，终端执行 `node --version` 确认。连接脚本已包含依赖，成员无需再安装 npm 包。
- 准备 Java 版 Minecraft。房主与成员版本、加载器和模组应一致；joincraft账号不代替 MC / 微软账号。
- 保留房主的游戏世界和连接程序终端窗口。这里转发的是房主本机 MC 世界，VPS 不运行游戏世界。
- 目前用户应用仍仅在开发 Mac 的 `127.0.0.1:4180`，这个地址不能在另一台 Windows 上直接访问。
- 同机测试时可将项目复制到 Windows，进入项目目录执行 `npm ci`、`npm start`，然后打开 `http://127.0.0.1:4180`。不要复制开发电脑的 `data/`、`.env` 或测试凭据。
- 两台异地电脑测试前，需要另行把本项目部署到 VPS 并配置可信 HTTPS / WSS 地址。当前尚未部署这次联机中继。已有探针服务不等于此联机服务。

## 房主

1. 在网页创建房间，进入房间概览。
2. 在 MC 中打开世界，按 Esc → 对局域网开放 → 创建局域网世界。
3. 记下 MC 聊天栏显示的端口。它不是网页房间号，重新开放世界后可能改变。
4. 点击网页「开始联机」，填写该端口，进入下一步。
5. 下载 `joincraft-bridge.cjs`。在下载文件所在文件夹打开 PowerShell 或终端，粘贴网页生成的 `node joincraft-bridge.cjs --connect ...` 指令。
6. 连接程序实际查询 MC Java 状态成功后，网页显示「可以加入游戏」。错误端口不会显示为成功。
7. 把网页房间号和房间密码告诉朋友。不要分享个人连接指令。

## 成员

1. 使用自己的joincraft账号 / 访客身份，输入房间号及密码加入。
2. 房主开房成功后，点击「连接游戏」。
3. 下载连接程序，在成员自己的电脑上运行网页给出的指令。
4. 网页和终端会显示类似 `127.0.0.1:54321` 的本机地址，端口动态分配，以实际显示为准。
5. 在 MC「多人游戏 → 直接连接」输入完整地址。
6. 这个地址只能用于运行该连接程序的电脑；在另一台设备打开同一账号网页，不代表另一台设备已经建立本地入口。

指令有效期 5 分钟，仅可启动一次。过期、关闭程序或断网后，请在网页重新生成指令。当前不自动重连，也不会自动启动游戏或下载模组。房主和成员的连接程序都需要保持运行。

## 应检查的真实游戏行为

| 场景 | 期望 |
| --- | --- |
| 正确版本 / 模组 | 可以进入世界、移动、交互、加载区块 |
| 错误端口 / 未开放局域网 | 房主收到明确错误，成员不能连接 |
| 未加入房间 / 密码错误 | 不能获取成员连接凭据 |
| 房主停止联机 | 所有成员游戏连接断开；房间本身仍保留 |
| 成员断开或退出房间 | 只回收该成员连接，其他成员不受影响 |
| 房主终端退出 / 游戏世界关闭 | 状态转为断开；游戏关闭的检测通常在约 10–14 秒内 |
| 拔网线 / 休眠 | 心跳失败后回收连接，需重新生成指令 |
| 第二次开房 | 可建立新连接，旧指令不能再次使用 |
| 持续游玩 30 分钟 | 记录延迟、掉线、CPU / 内存 / VPS 流量情况 |

同一台电脑如要验证完整游戏登录，需要能同时运行房主与成员实例，并使用游戏允许的不同玩家身份。仅通过 Java 状态查询或服务器列表看到 MOTD，不能算已经成功进世界。此项目不更改 Minecraft 的正版认证或玩家身份规则。

## 已完成的模拟检查

- Java 状态协议通过房主程序、服务中继和成员程序完整往返。
- 2 MB 二进制数据经过同一路径完整往返，使用流背压控制缓冲。
- 单独下载的连接脚本可运行，不依赖项目内 `node_modules`。
- 房主 / 成员权限、一次性及过期凭据、跨站握手拒绝。
- 停止、退出房间、退出登录、房主进程掉线、重新开房、非 MC 端口。
- 浏览器验证双方操作、状态同步、生成本机地址、桌面与窄屏表单。

这些检查不能替代真实游戏、Windows 实机、TLS 反代、异地网络、持续负载和模组兼容性测试。
