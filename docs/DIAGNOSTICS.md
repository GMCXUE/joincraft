# 客户端故障诊断

游戏库选择实例后打开「故障诊断」，可重新检查并导出 JSON 报告。启动异常退出时也提供直接入口。仅处理 Joincraft 自有实例，不读 PCL 目录，不上传日志、不自动修改游戏文件。

诊断包含当前客户端会话中的启动输出、操作失败信息、退出码，以及当前实例 `logs/latest.log`、`logs/debug.log` 和最近两份崩溃报告。每份文件最多读取末尾 128 KiB；本次启动存在时忽略此前的旧日志。异常日志目录和符号链接会跳过并提示。启动标准输出及错误输出持续消费，保留有限尾部，避免管道堵塞。

识别常见 Java 版本或架构、内存、缺失前置、重复模组、Mixin 兼容、游戏依赖、网络、磁盘和权限错误。结果为特征匹配的排查建议；未知问题明确显示无法识别，不把没有匹配项等同于游戏正常。

报告在传给页面和导出前隐藏已知游戏令牌、常见凭据字段、认证和 Cookie 头、URL 参数、邮箱、用户目录及 IP。导出位置由用户选择，仅保存本次收集的诊断内容，不包含完整启动命令、账号缓存或存档。新型模组可能把私人信息写入非标准字段，分享报告前仍可自行检查。

验证包括真实 Node 子进程输出与异常退出模拟、常见错误分类、脱敏、超大日志、过期报告、空报告和符号链接隔离；界面在隔离预览中验证入口、日志展开、导出反馈和 850×600 布局。没有启动 Minecraft 或执行 JAR。
