# 存档备份、恢复与迁移

客户端游戏库 → 存档：选择世界，点击「立即备份」或「导出 ZIP」。每个世界右侧的「备份与恢复」可查看该世界的历史备份，包括主信息损坏、无法直接启动的世界。恢复需要确认，客户端会先为当前世界创建独立安全备份，再切换为所选版本。恢复不会合并两个世界。

支持导入单个世界文件夹或 ZIP。ZIP 可直接包含 `level.dat`，也可只包含一层世界文件夹；多世界包、越界路径、符号链接、重复大小写路径、加密条目和超限内容会拒绝。导入总是新建独立世界，不覆盖已有世界，不修改导入来源。导出的 ZIP 根目录为世界内容，可用于其他实例的导入。

备份位于当前自有实例 `.minecraft/.joincraft/world-backups/<备份 ID>/`：`manifest.json` 记录世界、时间、文件大小及 SHA-256，`world/` 保存世界内容。仅备份选定世界，排除 `session.lock`，不包含账号、Java、模组或游戏缓存。备份不随房间整合包发布，也不会复制到编辑副本。迁移到其他磁盘时可导出 ZIP。当前没有自动清理已完成备份或云端上传。

仅操作 Joincraft 自有实例。游戏正在检查、启动或运行，以及安装、模组和其他存档任务进行时，禁止新的写入。所有存档写入串行执行；进度显示实际文件与已复制字节，扫描、校验和压缩阶段不编造百分比。切换世界目录时暂不允许取消，其余文件流支持取消；取消不修改原世界，也不会登记半成品。

备份先写入临时目录并逐文件校验，再原子登记。恢复验证备份并留下当前世界的安全副本，使用日志记录目录切换；失败立即回滚，应用异常退出后在下次操作或启动游戏前恢复未完成的切换。未完成的复制、导入暂存会清理，已完成备份保留。Windows 文件占用会有限重试，失败保留可恢复记录。

单个世界当前上限为 64 GiB、100,000 个文件、64 层目录；操作前检查可用空间，并为失败恢复保留余量。外部程序仍可能修改世界，客户端会检测文件和清单变化并拒绝登记；操作前应退出其他程序启动的游戏。

验证覆盖完整备份、空文件、自动安全备份、损坏世界恢复、哈希错误、空间不足、游戏锁、并发、取消、文件变化、路径和符号链接、目录切换失败、回滚失败后的下一会话恢复，以及 ZIP/文件夹迁移。界面使用隔离模拟数据检查，不替代 Windows 文件占用和真实大型世界实测。
