# 客户端更新

Windows 首次从官网下载 `.exe` 安装程序，0.9.10 起创建桌面和开始菜单快捷方式，并注册系统卸载入口。后续更新继续使用 0.9.4 引入的 joincraft 自带更新助手，不运行安装向导。客户端内下载完整 ZIP，校验、解压准备就绪后退出，等待原进程结束并替换应用目录，再重新启动。网页端不显示更新入口；macOS 继续使用 electron-updater 的签名 ZIP 更新路径，尚未发布正式 Mac 包。

## 使用和首次迁移

从官网点击「下载客户端」得到 `joincraft-setup.exe`，退出已运行的客户端后安装。默认仅为当前用户安装到 `%LOCALAPPDATA%/Programs/joincraft`，允许选择其他可写目录，不请求管理员权限。旧版 0.9.0–0.9.3 可通过这次安装迁移；ZIP 用户也可以选择安装。已有 0.9.4+ 用户继续应用内更新即可，无需重新安装。无需另外安装 Go、PowerShell 脚本等更新运行环境；Go 仅用于开发机编译助手。

主程序沿用原来的 AppData/Blockroom 配置目录，因此登录状态、游戏库目录和 Java 选择可继续读取。PCL 整合包与存档保留在原位置。安装版自动创建快捷方式；应用内替换仍使用同一路径。卸载程序和自定义卸载图标会在更新准备时按固定白名单保留，复制失败会在原应用退出前中止。卸载不删除账号与游戏库设置，也不删除外部 PCL 整合包或存档。

后续在右上角铃铛查看新版本 → 下载更新 → 重启更新 → 应用内确认。仍在游戏中时可以下载，必须先退出游戏再更新。更新期间禁止启动新游戏；确认后保存设置。替换文件前先解压验证整个新版，并确认目录可写，准备失败时保持当前客户端运行。重启会断开房间/语音连接。

启动 3 秒后检查，之后每 6 小时检查，只提醒一次，不自动下载或普通退出时偷偷更新。已确认的新版本重启后不会反复提示；更新取消/失败可重试。

## 校验与恢复

- 固定 HTTPS 源 https://www.joincraft.top/updates/windows-x64.json，禁止跟随重定向和远程页面指定下载 URL。只接受更高的正式版本和本平台架构。
- 清单使用 Ed25519 签名，客户端和原生助手各自内置公钥；清单绑定包名、平台、版本、字节数和 SHA-512。私钥留在开发机项目外，不上传服务器、不打包。
- 主进程流式下载并验证完整包，助手独立复验签名和散列，拒绝 ZIP 路径穿越、符号链接、重复路径、Windows 设备名与超限文件。替换包含 Electron 运行时和 app.asar 的完整应用，可一并升级运行时。
- 助手在应用配置目录运行，通过原进程句柄等待退出并核对进程的实际 EXE 路径；目录被占用时重试，不结束任意用户进程、不提权、不回退调用安装器。
- 同一磁盘上将原目录改名备份，然后将完整新目录切换到原路径，快捷方式地址不变。替换失败时恢复原目录；新版立即退出或无法启动则尝试恢复并启动原版。60 秒内仍运行但未报告页面就绪时保留新目录和备份，记录未确认状态，不强杀进程。
- 新版首次页面加载完成后写入启动确认。旧版本备份留在安装目录旁的 .joincraft-old-UUID 目录，未确认或失败包可能保留用于恢复。当前版不自动删除历史备份；每次更新需要额外空间容纳完整解压目录与备份。确认长期使用正常后可手动清理旧备份。
- 下载、确认与更新 IPC 仍只对固定本地通知页面主框架开放，网页及子框架不能调用文件替换。

## 构建与发布

开发机使用 Node.js 24 与 Go 1.25+，执行 `npm run dist:win` 同时构建首次安装 EXE 和应用内更新 ZIP；`npm run dist:bundle` 仅构建内部更新包。脚本编译无第三方 Go 模块的 Windows x64 GUI 助手，构建统一目录 payload 并写入版本标记。ZIP 与 NSIS 安装程序使用同一目录，不重新打包不同的应用内容。产物为 `release/joincraft-VERSION-win-x64-setup.exe`、`release/windows-x64-setup.json`、`release/joincraft-VERSION-win-x64.zip` 和 `release/windows-x64.json`，两份清单分别以固定 Ed25519 发布密钥签名。安装程序仍需 Windows Authenticode 证书才能显示已验证发布者；Ed25519 清单并不等价于 EXE 系统签名。

JOINCRAFT_GO 可指定 Go 路径；JOINCRAFT_UPDATE_SIGNING_KEY 指定 Ed25519 PKCS8 PEM 私钥，默认在 ~/.config/joincraft-release/update-ed25519.pem。公钥固定在 desktop/update-config.json，构建时注入原生助手。签名密钥不匹配时拒绝发布。丢失私钥必须重新迁移客户端，不能只替换服务器公钥。

CI 需要 Secrets.JOINCRAFT_UPDATE_PRIVATE_KEY，写入 runner 临时目录并构建；Windows Authenticode 证书可另配 WINDOWS_CSC_LINK / WINDOWS_CSC_KEY_PASSWORD。更新包的 Ed25519 签名与操作系统 EXE 签名是不同机制；本次测试分发尚无 Windows 发布者证书。

先上传版本 ZIP，验证签名、大小和散列，最后原子替换 windows-x64.json。旧 NSIS latest.yml 停留在 0.9.3，防止未迁移客户端再次尝试报错的安装流程。旧版二进制保留，不覆盖。服务器目录 /var/lib/docker/volumes/remotescreen_caddy_data/_data/joincraft-releases。

Mac 使用 npm run dist:mac，正式更新仍需 Developer ID 签名、公证以及 latest-mac.yml；用户的“不再运行安装器”请求本轮先落地当前 Windows 测试渠道。

## 0.9.6 内存分配
桌面游戏库新增自动配置与自定义滑块，每个实例独立保存。旧版已保存的 MB 数值迁移为自定义，新实例默认自动。主进程读取本机系统内存，只有可信本地游戏库可调用；不读取 VPS 内存作为玩家内存。

0.9.9 起，自动模式将当前系统可用内存全部设为游戏堆上限，以整 MB 为单位，不扣预留、不按 256 MB 向下取整，也不再受 8 GB、总量一半或 32 GB 限制。自定义上限为物理内存扣除预留量后、最多 32 GB，接近当前可用量时提醒。当前可用内存不足 512 MB 时拦截启动；512 MB 本身允许启动。检查文件和准备完成后、创建 Java 进程前再次读取系统状态，生成最终 -Xmx。

单条分段横条是分配预览，深色是当前系统占用，浅色是计划游戏堆上限，不能把它当成实际物理占用之和。超过剩余空间时浅色截断并以末端纹理标记，完整数值和超额提醒保留，悬停说明计算含义；运行后保持本次传入的堆上限，不表示 JVM 实时 RSS，也不在运行时修改 -Xmx。每 2 秒刷新可见游戏库，隐藏或被弹层覆盖时暂停轮询。

Windows 使用系统可用物理内存；Linux 使用 MemAvailable；macOS 通过 vm_stat 统计空闲、非活跃与推测页面作为保守估算，不重复加入可清理页面，并在界面标注估算。平台读取失败时使用保守的空闲内存回退。

新增测试覆盖系统统计、分配边界、自动模式忽略过期前端值、启动前重新评估、内存不足时不创建 Java 进程及平台差异。界面模拟验证模式切换、实例配置恢复和运行锁定，不执行真实游戏。截图中的额外内存清理功能不在本轮分配功能中。

## 0.9.9 自动分配语义
自动配置 = 当前可用内存全部作为游戏堆上限。界面每 2 秒同步可用量，创建 Java 进程前重新读取，以最后一次实际可用值写入 -Xmx。游戏运行后本次上限固定，不等于立即占用全部物理内存。自定义滑块的步长和范围沿用原设置。
